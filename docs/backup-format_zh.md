# 备份与存储格式

当前应用版本为 **v0.1**（`0.1.0`）。JSON 备份格式和本地存储格式分别使用 `version: 1`，与应用版本独立演进。升级格式必须提供明确迁移及测试；不支持的版本会被拒绝，原始数据保持不变。

## 完整备份与恢复

通过「显示 → 导出全部数据（JSON）」下载备份，通过「导入课表」恢复。导入先验证完整文件，再显示学期与课程安排数量，确认后替换全部课程、设置和偏好。JSON 恢复为完整替换；追加课程仍使用 Excel/CSV。无效文件不会修改当前数据。

正式定义见 [backup-v1.schema.json](../public/schemas/backup-v1.schema.json)，站点路径为 `/schemas/backup-v1.schema.json`。另附[有效备份示例](examples/backup-v1.json)。

| 字段                | 内容                                                |
| ------------------- | --------------------------------------------------- |
| `format`            | 固定为 `moving-on-schedule`                         |
| `version`           | 备份格式版本，当前为 `1`                            |
| `exportedAt`        | UTC 导出时间                                        |
| `schedule.courses`  | 全部安排，保留 ID、原文、颜色、备注、周次和排课方式 |
| `schedule.settings` | 学期名称、开始日期、周数和完整每日作息              |
| `schedule.isDemo`   | 保留示例文本与用户文本的区别                        |
| `preferences`       | 当前语言、主题偏好和周末／备注显示偏好              |
| `integrity`         | SHA-256 算法标识和 64 位小写十六进制校验值          |

`timing` 明确为 `period` 或 `time`。旧节次课程导出时补上 `timing: "period"`；节次为包含首尾的整数，时间为补零的 24 小时制 `HH:mm`，当天结束时间必须晚于开始时间。星期为 1（周一）至 7（周日）。ID 必须唯一，周次和节次不得超出设置。空白／部分填写的作息、重叠课程都会保留。

JSON Schema 检查结构、字段类型与范围；应用另外验证真实日期、作息先后顺序、课程时间顺序、ID 唯一性及周次／节次引用。校验值正确的无效课表同样会被拒绝。未知字段与版本会阻止导入，避免丢弃新格式的数据。

导出使用内存中的当前状态，包含未能保存到浏览器的修改；原始文本不随界面语言翻译，也不读取无关站点数据。当前查看周、搜索、弹窗、计算出的上课实例和系统解析后的主题属于临时状态，不进入备份。语言记录当前实际使用值，主题保留 `system` 等偏好值。

导入支持 UTF-8 JSON，可含 BOM，文件须小于 50 MiB。错误提示中的「下载原始数据」会保存原始存储键及对应文本，包括损坏内容；这种 recovery 文件用于排查与修复，不是可直接导入的正常备份。

## SHA-256 完整性校验

1. 仅移除文档根部的 `integrity` 字段。
2. 对象键递归按 UTF-16 code unit 顺序排序；数组顺序不变；基本值使用 ECMAScript `JSON.stringify` 的转义和数字规则，不添加空白、不做 Unicode normalization。这是本项目的 canonical JSON v1 算法。
3. 将结果编码为 UTF-8，用 Web Crypto 计算 SHA-256。
4. 将 32 字节结果转成 64 位小写十六进制字符串。

校验覆盖版本、导出时间和所有数据字段。调整缩进、对象键顺序不会改变校验值；修改课程顺序、备注或偏好会改变校验值。实现见 `src/integrity.ts`，测试使用独立的 Node crypto 进行比对。

该机制检测意外损坏和内容变化。校验值与数据一起保存，修改者也可以重新计算，因此不提供加密或身份真实性保证。JSON 文件是可读明文。

## 本地保存与多标签页

新存储键为 `moving-on-schedule.data`，一次写入完整的 `{ format, version, revision, data, integrity }`。其中 `data` 包含旧 `SavedData v1` 课表及全部偏好；随机 UUID `revision` 也参与哈希。启动时先验证 hash 和数据规则，之后才展示课表。损坏或不支持的数据不会自动覆盖，可先下载原文，再明确导入有效 JSON 修复。

新键不存在时，兼容读取旧课表、语言、主题、显示偏好四个键。首次用户修改后统一写入新快照；旧键保留作归档，迁移后不再参与当前状态。旧标签页需要刷新，其对旧键的修改不会更新新数据。只删除新键可能重新读出旧归档；要重新开始，可明确恢复空白 JSON 备份，或清除全部站点存储。

保存使用同源 Web Lock：比较编辑起点的原始快照、计算新 hash、再次比较、一次写入、回读并校验，全部成功后才在内部标记为已保存；正常保存时不显示状态行。同一标签页的连续修改排队处理。hash 用于完整性检查；锁和版本比较共同避免配合该协议的标签页互相覆盖。手动 DevTools 修改和不使用该锁的脚本不具备事务保证，额外比较和事件监听会尽可能检测变化。

其他标签页修改或清除数据时暂停写入，保留当前页面状态。「载入已保存版本」需要确认，建议先导出未保存修改。JSON 预览期间发生外部变化，也会阻止覆盖。恢复失败保留原内存状态。配额不足、禁止存储、回读不一致等情况均不报告成功；可导出内存修改或重试保存。应用会为未保存修改请求离页警告，具体行为受浏览器限制。

安全保存需要支持 Web Crypto 和 Web Locks 的浏览器及 HTTPS／localhost。不支持时拒绝自动写入。应用不尝试猜测无痕模式；成功回读仅代表本次写入成功，无法保证永久保留。无痕窗口关闭或浏览器清理／回收空间均可能删除数据，应保留独立 JSON 备份。

## 验证与诊断

- `npm test`：备份往返、hash、旧数据迁移、损坏、配额／权限失败、回读失败、连续修改、多标签页互斥。
- `npm run test:e2e`：真实 Chromium 下载与恢复、错误状态、双标签页及多语言响应式控件；首次可运行 `npx playwright install chromium`，或通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定兼容的本机 Chromium。
- `/build-info.json`：应用版本、commit、工作区是否有修改、构建时间和数据格式版本。无 Git 信息的源码归档会返回 `null`，首页不新增版本控件。
